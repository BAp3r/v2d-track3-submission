## 已落地的链路

```text
只读重建与原视频
  → 时轴、MANO拓扑、质量来源、尺度与世界坐标校验
  → 统一 loaded.parquet + 固定形态标定
  → 官方 Sharpa IK / 自有 multi-tip
  → 逐帧残差、速度、关节限位和手物表面诊断
  → 绑定输入哈希的机制验证门控
  → 相同 Sharpa / FlashCHORD 配置、三种子、单卡串行
  → 无辅助完整执行与实际物体轨迹
  → 只读查看器与中文报告
```

`dexpilot-chain-calibrated` 保留为诊断候选，本轮不迁移为第三组训练，不据失败临时替换候选或追加某组预算。

| 服务 | 负责的边界 |
|---|---|
| `sharpa_episode.py`、`sharpa_bridge*.py` | 单集来源、时间、MANO及世界坐标契约；拒绝长缺口和无效监督 |
| `sharpa_calibration.py`、`sharpa_multitip*.py` | 两侧固定形态比例、腕变换、22关节顺序与限位、两条离线求解路线 |
| `sharpa_geometry_audit.py` | 固定碰撞表面采样、米制最近距离、有限穿透诊断、质量与机制门控分离 |
| `policy_gate.py` | 当前视频、后端、重定向文件、标定、几何凭证的SHA绑定 |
| `policy_budget.py`、`policy_experiment*.py` | 冻结公平预算、全阶段课程、独立容器、保存恢复、串行三种子与真实评估 |
| `policy_checkpoint_audit.py` | 固定官方结构逐叶匹配，区分尝试更新、生效Adam更新与跳过率 |
| `policy_trajectory.py` | 每个环境和物体的全部帧、身份、时间、单位、姿态及失败标记校验 |
| `policy_scene_export.py`、`policy_rollout_export.py` | 运动学与实际执行分别导出；实际轨迹只读 achieved 字段 |
| `policy_view_data.py`、`vlm_compare_viewer.py` | 受限文件读取与哈希验证；API不训练、不转码、不修改数据 |
| `postprocess_*.py` | 同源多物体场景、遮挡歧义支持与深度源对照 |

重定向适配器声明名为 `nvidia-v2d-sharpa-offline-retarget`，版本 `1.0`，作用范围为单集；
输入为官方 MANO/Sharpa Parquet、可信形状标定及质量来源、Sharpa MJCF/mesh；
模式为 `official-ik`、`unidex-inspired-ik-v2`；输出 schema 为 `nvidia_v2d.sharpa_retarget.v1`。
这些依赖不导入平台的数据模型。实验运行记录、容器、模型、视频、Parquet、NPZ与机器本地状态不入Git。

## 标定与公平性

自有求解器来自用户仓库提交 `41efca631a91902c47da222eeaad81022e52220b`，原求解器字节保持不变，
SHA256 为 `d481806a25ead89e4e87877aeb8b5950f9c5273cd374010b301b6146569964bc`，来源记录随 vendor 源码保存。
未沿用 OmniHand SDK 十关节顺序。Sharpa 每侧22个运动关节，输出保持官方字段和关节名称。

采用可信 MANO 形状的规范展开姿态，分别估计固定的左右形态比例；不要求抓物视频提供张手帧。
形态比例只作用于腕部局部目标；不缩放物体、场景或世界腕轨迹。明确组合 MANO 解剖腕轴和机器人掌腕轴，
不把消除世界腕姿的遥操作标定直接当成完整世界运动。

桥接保留源视频20 FPS与249帧。实际 hand scale 约为左1.3257、右1.3132；忽略它会造成约3.3 cm误差。
运行时左 MANO 形态镜像与规范腕轴问题已修复，原MANO文件不改。首次失败的自有001结果仍保留；有效对照使用002。
最终桥接006将不存在的 MANO fitting residual 写为 null；对照使用的005几何完全相同，但其中历史0值明确代表未知，不能作为质量证据。

两路共用005输入、物体网格、时间轴与固定标定。官方IK允许优化浮动腕部，自有方案固定重建腕轨迹；
这是保留且披露的算法差异。未启用遥操作默认平滑或0.5 rad/s限速，原始速度和失败帧均保留。
